AI coding agent 已被广泛用于代码库维护与重构，但开发者对其「理解深度」始终存疑。OpenStation 博客的作者做了一次颇具挑衅性的实验：从代码库中删除 168,000 行注释，看看日常协作的 AI agent 会不会察觉异常。

结果是：agent 完全没有注意到。这个结果指向几种可能解释。其一，agent 主要依赖局部代码模式与语法结构做判断，而非注释所承载的意图与设计上下文；其二，它的验证信号来自编译、测试是否通过，而注释的消失不会影响任何自动化检查；其三，agent 的工作范围与注意力窗口偏局部，缺少对仓库整体风格与文档一致性的感知。

这一实验的价值在于划出信任边界。当人们把「代码库维护」交给 agent 时，隐含假设是它理解项目约定；但实验表明，语义层面的漂移可能长期不被发现，直到人类接手才暴露。后续值得关注：如何设计能检测文档与意图漂移的评测方法；注释与设计文档在 AI 时代是否仍然必要；以及人类代码审查与 agent 自动化之间该如何分工，才能在效率提升的同时守住可维护性。
