近两年，数学推理成为评测大模型能力的重要方向，而真正能解难题的系统，往往不是单靠模型本体，而是由模型调度外部工具构成的 agent：调用 Python 执行数值计算、调用符号计算库做化简、调用证明助手验证步骤，甚至检索文献与定理库。这种“模型 + 工具”的架构显著提升了成功率，但也把一个新的薄弱环节引入系统——工具返回的结果被默认信任。

这篇论文的题目《When Tools Lie: Reliability of Mathematical Agents Under Corrupted Tool Feedback》直指该问题：当工具反馈被污染、即返回错误或误导性信息时，数学 agent 的可靠性如何变化。作者关注的显然不是随机噪声，而是“工具说谎”这种更危险的情形——反馈看起来合理、格式规范，却与事实不符。此时模型是盲目采信并沿着错误方向继续推理，还是能通过交叉验证、量纲检查或多次独立计算察觉异常，直接决定最终结论是否可信。

后续值得延伸的方向有三：其一，评测体系需要把工具可靠性纳入变量，而不只是考察干净环境下的解题率；其二，工程上应引入冗余与验证机制，例如多工具交叉比对、关键结论的独立复算、以及对异常的显式上报；其三，这一议题的意义远超数学，凡是依赖外部 API 或数据库的 agent 系统，都面临相同风险。对部署者而言，最重要的启示是：agent 的能力上限，往往由它验证信息的方式决定。
