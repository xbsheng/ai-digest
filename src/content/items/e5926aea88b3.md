AI Agent 的评测体系通常由两部分构成：被测 Agent 与负责判定结果是否正确的验证器（verifier）。在编码、网页操作、工具调用等任务中，验证器可能是单元测试、状态检查脚本，或由模型充当的评审员。随着 Agent 能力提升，评测的可信度越来越取决于验证器本身是否可靠。

arXiv 论文 TRACE 聚焦于一个常被忽视的问题：验证器脆弱性（verifier brittleness）。当验证器对任务的约束不够严格、或存在可被绕过的判定路径时，Agent 可能在不真正完成任务的情况下获得高分。该论文提出一套诊断方法，用于识别验证器在何种条件下失效——例如边界输入、部分完成的中间状态、或与任务语义不一致的检查逻辑。这类问题的危险性在于，它不会表现为明显的崩溃，而是表现为「成绩虚高」。

对评测生态而言，这意味着排行榜上的分数需要附带验证器质量的说明。一个 Agent 在宽松验证器下的高分，与其他 Agent 在严格验证器下的同等分数并不等价。论文的价值在于把验证器从隐含假设变成显式研究对象，为后续构建更稳健的评测协议提供方法基础。

后续关注点包括：一是主流 Agent 基准是否引入验证器审计流程；二是能否形成验证器强度分级，让不同结果可比较；三是这一思路能否迁移到人类参与评审的场景，例如研究评审与竞赛评分中的核查机制。评测基础设施的可靠性，正在成为 Agent 进步速度的真实瓶颈。
